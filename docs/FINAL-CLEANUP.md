التعديلات محلية فقط: لا Commit أو Push أو تغيير في إعدادات الاستضافة. إن كانت نسختك أحدث، قارن الملفات قبل الاستبدال حتى لا تفقد عملًا جديدًا.

## ماذا نُظف؟

- Backend: إزالة alias غير مستخدم `countPendingByDonor` مع إبقاء `countPendingOffersByDonor` المستعمل؛ استيراد أنواع MongoDB من Mongoose بدل اعتماد transitive غير معلن؛ حماية معلومات رسائل البريد في logs مع إبقاء HTTP status؛ تنظيف قواعد Git ignore ومراجع TypeScript والتوثيق.
- Frontend: توحيد أنواع Dashboard وإزالة إعادة تصدير وتعريفات غير مستخدمة؛ تصحيح نص الكوتا الشهرية؛ تحديث `@humanfs/node` إلى `0.16.8` وتبعيات التصحيح؛ انتظار استجابة POST المحددة في اختبار التبرع بدل الانتظار الثابت وسجلات التشخيص.
- أداة قياس `perf:smoke` بلا dependencies إضافية، GET فقط، مع حدود للضغط وإيقاف عند الخطأ أو 429 أو التأخير. اختبارات جديدة للقياس ولسرية سجلات البريد.

لم تُحذف ملفات مصدر كاملة. لم تتغير قاعدة البيانات أو حسابات Demo أو عقود المصادقة أو طريقة التشغيل. لم تُعطّل Rate Limiting أو حماية production. Backend التشغيلي بقي TypeScript strict وNative ESM؛ اختبارات Node القديمة تبقى JavaScript معزولة في `test/` ولا تغيّر صيغة خادم الإنتاج.

## التطبيق

1. احفظ نسخة من تعديلاتك المحلية أولًا.
2. فك الأرشيف خارج المشروع. ادمج محتويات `backend/` داخل الباك، ومحتويات `aoun-frontend/` داخل الفرونت. استبدل الملفات المطابقة فقط؛ الأرشيف يحتوي التعديلات وليس المشروع الكامل.
3. لا تحذف أي ملفات يدويًا. لا تُشغّل seed ولا تمسح DB ولا تستبدل ملفات البيئة.
4. في Backend:

```powershell
npm ci
npm run verify
```

5. في Frontend:

```powershell
npm ci
npm run verify
npm run build
```

التطوير بقي `npm run dev` لكل مشروع. Render بقي `npm ci && npm run build` ثم `npm start`. لا ترفع ملفات البيئة أو `node_modules` أو `dist`. قواعد ignore لا تمحو سرًا سبق رفعه؛ إن سبق نشر اعتماد حقيقي، ألغِه وغيّره لدى مزوده.

## نطاق التحقق

الفحوص المحلية على Node.js 24.19.0. تحليل Knip لفئات files/dependencies/unlisted/unresolved لم يجد مشاكل متبقية في أي من المستودعين؛ هذه نتيجة ضمن إعداداته وليست إثباتًا لاستحالة وجود كود غير مستخدم.

نجح Backend `verify`: فحص الأنواع و152 اختبارًا والبناء. `npm audit` أبلغ عن صفر ثغرات معروفة في كلا المشروعين بعد التصحيح، وليس شهادة أمان شاملة. الاختبارات تضم عقودًا ثابتة ووحدات وبعض HTTP محلي؛ ليست بديلًا عن E2E.

نجح Frontend `verify`: lint وtypecheck و117 اختبارًا. تعذر إثبات اكتمال بناء Frontend هنا؛ أوقفت بيئة التنفيذ متابعة العملية برسالة `network approval was cancelled before a decision was returned`. لا نسجل البناء كـPASS؛ شغّل `npm run build` محليًا أو دع GitHub Actions يؤكده قبل النشر.

نجح أيضًا تحميل التطبيق المبني من `dist` بصيغة Native ESM وفحص HTTP محلي للصحة مع أداة القياس. أعاد readiness المحلي 503 و`database: disconnected` كما هو متوقع لبيئة بلا MongoDB؛ هذا ليس فحصًا لاتصال قاعدة الإنتاج.

لم تُشغّل دورة Playwright التي تنشئ طلبات وعروضًا على DB المنشورة. تحتاج بيئة وحسابات اختبار وكوتا متاحة وتفعيل `E2E_RUN_MUTATING=true`.
