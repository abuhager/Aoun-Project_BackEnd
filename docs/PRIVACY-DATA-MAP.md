# خريطة البيانات ومصفوفة الاحتفاظ — مسودة تشغيلية

هذه وثيقة هندسية وليست موافقة قانونية. يجب أن يعتمدها مستشار قانوني للبلد
المستهدف قبل Production.

| الفئة | أمثلة | الغرض | المعالج الخارجي | الاحتفاظ التقني الحالي | الإجراء المطلوب |
|---|---|---|---|---|---|
| الهوية | الاسم، البريد، الهاتف | الحساب ومنع الإساءة | Firebase للهاتف، Brevo للبريد | مدة الحساب | تحديد مدة ما بعد إغلاق الحساب |
| الأسرار | password hash، refresh hash، OTP hash | المصادقة | لا يوجد | OTP/جلسة حسب الصلاحية | اختبار محو الجلسات دوريًا |
| المحتوى | الأغراض، الطلبات، الصور | تشغيل التبرع | Cloudinary للصور | tombstone عند الحذف | اعتماد مدة tombstone والحذف النهائي |
| التواصل | المحادثات والرسائل | تنسيق التسليم | لا يوجد | تُؤرشف عند حذف الغرض | اعتماد مدة الرسائل وlegal hold |
| الثقة والإشراف | ratings، reports، audit logs | السلامة والاعتراض | لا يوجد | محفوظة للتدقيق | اعتماد مدة وحق الاعتراض/التصدير |
| البريد المتين | payload مشفر داخل Outbox | التفعيل والتنبيهات | Brevo | الأحداث المكتملة 30 يومًا | مراجعة DLQ والحذف |

## تمرين الحذف/التصدير

1. أنشئ نسخة اختبار معزولة واستعادة حديثة من backup.
2. اجمع كل المراجع بواسطة user id عبر User وItem وDonationRequest وOffer و
   Conversation وMessage وNotification وRating وReport وAdminLog.
3. طبّق policy المعتمدة: حذف، إخفاء هوية، أو legal hold. لا تفصل السجلات
   المرجعية بلا tombstone.
4. اطلب حذف الأصول الخارجية (Cloudinary/Brevo/Firebase) وسجل confirmation
   لا الأسرار أو المحتوى نفسه.
5. شغّل `npm run db:orphans:audit` وتحقق من عدم وجود مراجع يتيمة.
6. أنشئ export للمستخدم، افحصه يدويًا، ثم احذف بيئة التمرين.

المالكون المطلوبون قبل الإطلاق: مسؤول قانوني، مسؤول أمن، ومالك المنتج.
